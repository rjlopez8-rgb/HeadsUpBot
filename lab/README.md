# How our bot works, and how to test it

## What plays in the tournament

`agent.py` → `solverbot.HybridX`, which uses:

| File | Role |
|---|---|
| `data/strategy.npz` | **The blueprint**: a game-theory strategy computed by CFR+ for every betting situation (43,081-node tree generated by the official `game.py`) and 20 hand-strength groups per street |
| `data/preflop_eq.npy` | Exact preflop strength of all 376,992 starting hands (it must be the table the blueprint was trained with) |
| `data/pt_table.npy`, `fasteval.py` | Hand scoring that is 47x faster than `evaluator.omaha_score` and agrees with it exactly |
| `pokerlib.py` | Monte Carlo equity, the opponent range model |
| `solver/features.py` | E[HS²] (hand strength including draws), computed the same way in training and play |
| `hero.py` | Exploit engine and opponent tracking, and the last-resort fallback |

**How it decides:**
1. Find the exact node in the betting tree from the actions so far.
2. Put our hand in a group (preflop: table; flop/turn: E[HS²]; river: strength) and sample the blueprint's mixed strategy for that node and group.
3. For the first 100 hands, play the pure blueprint while measuring the opponent's raise rates and how often it folds to our bets. If those are far from equilibrium (0.47 / 0.39 / 0.41), switch on targeted overrides:
   * R1: against players who rarely raise, check our equity against their real (narrow) raising range and fold when it is behind.
   * R2: against players who rarely fold, stop bluffing and bet medium-strong hands for value.
   * R3: against players who fold too much, bluff more.
   * R4 (call down maniacs) is **off**. The red team showed that aggressive bots exploit it.
4. Against a bot that folds to almost every bet (for example, one whose time bank ran out), raise every hand.
5. Time guard: aim for 2 s of the 8 s bank and cut the sample counts in stages if it falls behind (the estimate includes HTTP overhead).
6. Any exception falls back to `hero.py`, then to CHECK_CALL. It never crashes.

## Results (all reproducible with the commands below)
* Simulator = official judge: identical bb/deal and interval on the same seed.
* Pool of 15+ opponents (AI-typical Monte Carlo bots, bots using the official evaluator, the guide's example, weird styles, an adaptive exploiter): **every match won**.
* Red team: 42 generated attackers in 3 rounds, aimed at our rules. After the R4 fix, **none beat us**.
* Solver vs solver: finer abstraction wins (K=20 > K=16 > K=8; K=24 didn't help). E[HS²] beat E[HS].
* Timing: 3.4–3.7 s of 8 s with a CPU hog on our core (about 1.5 s normally). 0 errors. Startup is about 1.5 s.
* Official smoke test passed on a read-only, non-root copy of the repo.

## Commands
```bash
pip install numpy fastapi uvicorn pytest
python -m pytest -q                                   # official tests + test_ours.py

# evaluate versions against the pool and each other (ranked by worst matchup)
python lab/evaluate.py --cands hybridX solver --deals 1000 --seeds 2
# add any agent.py (e.g. a bot an LLM wrote, or a teammate's) as an opponent
python lab/evaluate.py --cands hybridX --extra path/to/other/agent.py

# red team: generate attackers and look for anything that beats us
python lab/redteam.py --target hybridX --n 30 --seeds 2 --rseed 5

# timing under CPU contention with the official judge (Linux, needs taskset)
bash lab/stress_time.sh 1000

# the organizers' build check (needs Docker; run before submitting)
./tools/check_build.sh
```

## Rebuilding the blueprint (offline, hours of CPU)
```bash
python solver/preflop_table.py --canonical --samples 4096   # data/preflop_eq.npy
python solver/dataset.py --n 300000 --seed 3 --tag c          # deals (repeat with new seeds/tags)
python solver/features.py --tags c d e f g                    # E[HS^2] features
python solver/cfr.py --data c d e f g --feature h2 --K 20 --iters 5000 --out solver/data/strategy_new.npz
cp solver/data/strategy_new.npz data/strategy.npz             # ship it with the matching preflop table
```
